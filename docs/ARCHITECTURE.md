# 架构与验收说明

## 公开边界

本仓库只复现科研协作系统的一条完整软件链路，所有输入都是虚构示例。不包含文献在线检索、未公开的研究假说、真实催化剂配方、原始实验数据或实体实验执行。

`EvidenceCard` 是演示中唯一的来源记录，其 `source_ref` 必须以 `demo://` 开头，证据类别为 `SYNTHETIC`。角色报告和会议发言只能引用已有证据卡编号。即使软件审查全部通过，这些发言仍属于讨论草案。

## 阶段契约

| 阶段 | 输入 | 产物 | 阻断条件 |
| --- | --- | --- | --- |
| 独立分析 | 议题与证据卡 | 每个角色一份报告 | 缺少角色、内容或有效证据引用 |
| 分支会议 | 会前报告、分支视角、该分支的会话记录 | PI 开场与裁决、其余角色发言 | 角色缺席、来源编号无效或 fallback |
| 跨分支汇总 | 各分支草案 | 共识、争议、否决理由、未决问题 | 会议 QA 未通过 |
| 最终门控 | 会议 QA 与候选方案编号 | 放行或阻断状态 | 会议发现问题、候选编号重复或选择无效 |
| 研究者选择 | 候选方案集合 | 明确的候选编号 | 未选择则等待；编号无效则阻断 |
| 实验设计审查 | 已选候选方案 | 审查发现 | 缺少对照、测量指标、判定规则或来源依据 |
| 下一轮计划 | 审查通过的方案 | 实验矩阵与建议 | 任一上游门控未通过 |
| 结果反馈 | 与实验编号匹配的虚构结果 | 待复核反馈 | 实验编号不匹配或示例来源定位无效 |

`OpenAIBackend` 是可选的草案生成接口。它的输出必须经过与离线案例相同的 Pydantic 解析和后续门控。仓库中的离线测试使用假后端验证角色顺序与分支隔离，**不代表真实模型调用已经验收**。

## 已覆盖的离线验收

1. 完整的虚构案例达到 `COMPILED`，实验矩阵和决策追踪保留已选候选编号与证据编号。
2. 分支 fallback 阻断实验矩阵和下一轮建议。
3. 缺少对照时，会议 QA 可通过，但已选方案会被实验设计审查阻断。
4. 引用未知证据编号会阻断会议 QA。
5. 缺少研究者选择时，不编译实验方案。
6. 实验结果编号不匹配时，在写入产物前拒绝处理。
7. 各角色独立提交会前报告，每个分支均从空会议记录开始。

这些是软件行为验收。来源真实性、模型推理质量和实验可行性仍需研究者另行审查。
